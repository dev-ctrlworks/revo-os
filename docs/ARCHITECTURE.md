# Architecture

Revo OS is a working prototype of an AI memory layer. It is a single Next.js
App Router application that renders a marketing site and a local-first demo
app, deployed to Cloudflare Workers via OpenNext.

## Goals of the architecture

- **Local-first by default.** Everything the user captures lives in the
  browser (`localStorage`). No account, no server-side memory storage.
- **Small, stateless server surface.** Only four things need a server: AI
  answers (`/api/ask`), the waitlist, feedback, and a privacy export/delete
  endpoint. All of these are edge-friendly and stateless.
- **Static, cacheable pages.** Pages are static (no request-time nonce) so
  they can be cached at the edge; security is enforced with a static CSP plus
  response headers.
- **One deploy target.** The same codebase runs on `next dev`,
  `next start`, and Cloudflare Workers through `@opennextjs/cloudflare`.

### Route map

Marketing / static:

- `/` — landing page (`src/app/page.tsx`), server component.
- `/privacy`, `/terms`, `/privacy/request` — legal + data request.
- `/sitemap.xml`, `/robots.txt` — generated by `sitemap.ts` / `robots.ts`.

App (route group `(app)`, wrapped by `src/app/(app)/layout.tsx`):

- `/dashboard` — home feed, metrics, heatmap, quick actions.
- `/search` — AI ask + grounding sources.
- `/capture` — five capture methods.
- `/timeline` — chronological browse.
- `/collections`, `/collections/[slug]` — grouped memories.
- `/graph` — relationship graph of memories and entities.
- `/memory/[id]` — detail view for a single memory.
- `/settings` — preferences, storage usage, data controls.

API (route handlers):

- `/api/ask`, `/api/waitlist`, `/api/feedback`, `/api/counts`, `/api/privacy`.

## Rendering and data flow

### Local-first memory model

`src/lib/memory-store.ts` is the single source of truth for memories on the
client. It merges:

1. **Base (demo) memories** — `src/lib/mock-data.ts`, shipped with the app.
2. **Captured memories** — written to `localStorage` under
   `revoos.captured.memories.v1`.
3. **Edits** — per-id patches under `revoos.memory-edits.v1`.
4. **Collection metadata overrides** — `revoos.collection-meta.v1`.
5. **Deleted ids** — `revoos.deleted-memories.v1` (tombstones for base data).

`getAllMemories()` composes these into the effective list. Writes call
`notify()`, which rebuilds a cached snapshot and fires store listeners.
Components subscribe through `useMemoryStore()` (`src/lib/use-memory-store.ts`)
using `useSyncExternalStore`, with a server snapshot that returns only the
base memories to keep SSR deterministic. Hydration from `localStorage` is
deferred to a `useEffect` (`syncFromStorage`) so the first client render
matches the server.

Storage is capped at ~5 MB; on `setItem` failure the store raises a
`STORAGE_FULL_MESSAGE` that the capture UI surfaces.

### Derived logic (all client-side)

- `src/lib/ai.ts` — tokenized keyword search (`searchMemories`), related
  memories, grouping, and the canned answer generator used as a fallback.
- `src/lib/summarize.ts` — extractive summary/description/key-point generation
  (frequency-scored sentence selection) used when a memory is captured.
- `src/lib/graph.ts` — builds a graph of `memory` and `entity` nodes and typed
  edges (`part-of`, `mentions`, `related`, ...) for the graph view.
- `src/lib/collection-meta.ts` — resolves collection emoji/description/color.

### Server interaction

The client only calls the server for AI answers and the public waitlist /
feedback / privacy flows. On `/search`, the client sends the query plus the
top matching memories as `sources` to `/api/ask`; the server re-validates,
truncates, and forwards them to OpenAI, returning either `{ answer }` or
`{ fallback: true }` (the client then falls back to `generateAnswer`).

## Configuration

- `next.config.ts`
  - `images.unoptimized: true` (Workers runtime).
  - `poweredByHeader: false`.
  - `skipTrailingSlashRedirect: true` (required so the PostHog proxy paths
    are not rewritten to `/ingest/.../`).
  - `rewrites()` proxies `/ingest/*` to PostHog (US) to avoid ad blockers and
    keep first-party.
  - `headers()` injects the static security header set on `/(.*)` and
    `Cache-Control: no-store` on `/api/*`.
- `wrangler.jsonc`
  - Worker name `revoos`, `main: .open-next/worker.js`, static assets from
    `.open-next/assets` bound as `ASSETS`.
  - `nodejs_compat` + `global_fetch_strictly_public`.
  - `RATE_LIMITER` binding (simple limit: 30 req / 60 s, namespace `1001`).
  - Custom domain route `revoos.ctrlworks.co`.
- `tsconfig.json` — path alias `@/* -> ./src/*`, `strict`, `moduleResolution:
  bundler`, includes `.next/types` and `**/*.mts`.
- `eslint.config.mjs` — flat config extending `eslint-config-next`
  `core-web-vitals` + `typescript`, ignoring `.next`, `.open-next`, `.wrangler`.

## Build and deploy pipeline

| Command | What it does |
| --- | --- |
| `npm run dev` | `next dev` on `:3000`. |
| `npm run build` | `next build` (Node target). |
| `npm run lint` | `eslint`. |
| `npx tsc --noEmit` | Type check. |
| `npm run build:cf` | `scripts/build-cf.sh` — temporarily moves `.env.local` / `.dev.vars` aside, runs the OpenNext Cloudflare build, then restores them (so secrets are never baked into the bundle). |
| `npm run preview:cf` | OpenNext build + local Workers preview. |
| `npm run deploy:cf` | `scripts/deploy-cf.sh` — build (secrets stripped) then `wrangler deploy`. |

Runtime secrets are set per-worker with `wrangler secret put` (`OPENAI_API_KEY`,
`OPENAI_MODEL`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`). Public values live
in `.env.production`. See `SECURITY.md` for the secret model.

## Key decisions and trade-offs

- **localStorage over a database for memories.** Keeps the prototype
  zero-signup and private, at the cost of per-browser persistence, no sync, and
  a ~5 MB ceiling.
- **Static CSP instead of nonce-based CSP.** Earlier nonce CSP required
  request-time rendering; it was reverted in favor of static pages and a
  `'unsafe-inline'` script/style policy scoped by origin. Simpler, cacheable,
  and sufficient for this prototype.
- **Keyword search on the client, LLM only for synthesis.** The server never
  receives the whole memory corpus — only the up-to-6 sources the client
  already selected.
- **Analytics reversed-proxied and consent-gated.** PostHog is loaded only
  after consent, and server events are emitted only when the client sends a
  consent-derived distinct id.
